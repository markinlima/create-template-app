# Folder structure

Where each kind of code goes in `apps/web`. The app is split into **global
folders**, shared by the whole app, and **modules**, one per feature or area.
A module mirrors the global folders on a smaller scale.

## The app folder

- **`src/`** — the browser SPA, described below.
- **`server/`** — the Nitro server of the build, run by Bun. `web-server.config.ts`
  is its entry; `constants/` and `utils/` hold what it uses (security headers,
  cache rules, server env, frame ancestors). It is server-only and never imports
  from `src/`. Its rules, cache and health check are in [server](./server.md);
  the tags of the pages (prerender and dynamic) are in [seo](./seo.md).
- **`scripts/`** — one-off tools behind the scripts of `package.json` (OpenAPI
  generation, the Kubb patch, image optimization). They are not shipped to the browser.
- **`public/`** — files served **as they are**: no import, no transformation,
  no TSX. The code reaches them by URL (`/images/pwa/icon-512.png`). It holds:
  - static images (`images/`, grouped by use: `pwa/`, `head/` for OpenGraph and
    social images, and so on), and videos (`videos/`);
  - third-party scripts (`ads/`);
  - plain files served at the root: `robots.txt`, `ads.txt` (or `app-ads.txt`),
    `manifest.json` (PWA), the favicon.

  A file goes here when nothing in the code needs to render it as a component.

## `src/`: global folders

| Folder        | What goes in it                                                                                                                                                                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `gen/`        | The API layer generated by Kubb. Never edit it (see [query-cache](../react/query-cache.md)).                                                                                                                                                                                             |
| `assets/`     | Icons and logos converted to React components (`.tsx`), imported in code. They take props such as size and color and inherit `currentColor`. Subfolders `icons/` and `logos/`. All of them are SVGs today, which is why they are components. Raster and large media go in `public/`. |
| `components/` | Global presentational components used on any route: the status screens (`status/`: not found, route error, splash, maintenance), `brand/`, `devtools-wrapper`.                                                                                                                       |
| `layout/`     | Global pieces of the app shell that frame many pages: headers, sidebars, footers. One folder per piece (`header/`, `sidebar/`), because an app may have more than one header or sidebar. Routes render them from their layout route (see [routes](../react/routes.md)).              |
| `core/`       | App constants and config: `routes.ts` (default URLs), `cache.ts`, `alerts.ts`, `info.ts` (brand), `phrases.ts`, `themes/`.                                                                                                                                                           |
| `hooks/`      | Global hooks, such as `use-custom-hook-options.ts`, and the per-endpoint cache rules in `custom-hook-options/`.                                                                                                                                                                      |
| `lib/`        | Configuration of external libraries, one folder each: `axios`, `env/` (the only env access, through `clientEnv`), `tanstack-query`, `sentry`, `seo`, `analytics`, `infinite-list`, `vite` (build plugins).                                                                           |
| `modules/`    | Features and areas of the app. See below.                                                                                                                                                                                                                                            |
| `routes/`     | File-based routes of TanStack Router. Thin: they compose modules and global components.                                                                                                                                                                                              |
| `schemas/`    | Zod schemas used across modules, such as forms and validation that Kubb does not generate.                                                                                                                                                                                           |
| `styles/`     | The Tailwind entry, base styles, utilities and animations.                                                                                                                                                                                                                           |
| `types/`      | Global types: ambient declarations, the generated route tree and image types.                                                                                                                                                                                                        |
| `utils/`      | Generic helpers used across modules, one function per file.                                                                                                                                                                                                                          |

- **There are no global contexts or stores.** A React context or a Zustand
  store belongs to the module that owns its state, so it lives in that module's
  `context/` or `stores/` folder.
- **`components/` or `layout/`?** `layout/` holds the pieces of the shell that
  frame the pages. `components/` holds everything else that is global. A header
  that belongs to one area of the app (its own logic and state) lives in that
  area's module.
- **Global code goes in the root.** If something is used by several modules and
  is not tied to one of them, move it from the module to the root folder.

## Modules

`src/modules/` holds the features and areas of the app. Each module is a
**mini `src`**: it contains every component, hook, store, context, constant,
type and util that is specific to one area, so the global folders stay small.
Examples are `comments` or `profile`: a module keeps the components, hooks and
utils of that feature together.

- **Only code of its area.** Use the same subfolders a `src` would have, created
  only as needed:
  - `components/`: the module's components (see [component-patterns](./component-patterns.md)).
  - `hooks/`: its hooks, one per file, named `use-*`.
  - `context/`: its React contexts (the context, its provider and its hook), for
    state shared by the components of a part of the module.
  - `stores/`: its Zustand stores, named `*-store.ts`, following [zustand](../react/zustand.md).
  - `schemas/`: Zod schemas only this module uses (see [schemas](../typescript/schemas.md)).
  - `constants/`, `types/`, `utils/` and `lib/`, as a `src` would have them.
  - `pages/`: only in the landing pages, one folder per page.

  Reuse the names the existing modules already use. Don't invent synonyms
  (`data`, `api`, `helpers`, `style`, `store` for `stores`, `contexts` for `context`).
- **Placement.** A module of the authenticated app (`/app/*` routes) lives under
  `modules/app/<module>`. Cross-cutting modules sit directly in `modules/`; in the
  web template these are `auth`, `form`, `landing-pages` and `privacy`.
- **Within a module**, big components get their own folder grouped by kind
  (`buttons/`, `dialogs/`, `feed/`, `states/`, `presets/`, ...) instead of one
  flat list.
- **Dependencies** flow from specific to generic. Modules may import from each
  other and from the global folders, but avoid import cycles between modules.
- **API data does not live in modules.** Generated hooks come from `@/gen/api`;
  per-endpoint cache behavior goes in the global custom hook options (see
  [query-cache](../react/query-cache.md)).
- **Names**: kebab-case files, hooks named `use-*`, stores named `*-store`.
- **Routes stay thin**: they compose module components and do not hold feature logic.
  The exception is a small schema that validates only that route's params or search, which may sit
  in the route file above `createFileRoute` (see [routes](../react/routes.md)).
