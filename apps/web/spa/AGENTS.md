# Web SPA — AI Instructions

## What it is

Template of a React single-page app (client only) built with [Vite](https://vite.dev/) and [TanStack Router](https://tanstack.com/router). Same structure as `../mpa`; only the setup differs.

## Setup specific to the SPA

- `index.html` + `src/main.tsx` are the entry; the `<title>`/description of the first paint live in `index.html` (there is no SSR).
- `vite.config.ts` — `@tanstack/router-plugin` (reads `tsr.config.json`); the build goes to `dist/`, served by nginx (`nginx.conf` falls back to `index.html`).
- `src/router.tsx` exports `createRouter({ queryClient })`; `src/routes/__root.tsx` renders `<HeadContent />` and the providers.
- `lib/env/client.ts` is the only env (`VITE_*`); use `clientEnv`, never `import.meta.env` directly.
- `lib/axios` and `lib/tanstack-query` are plain browser code (one `QueryClient` for the tab).

## Project structure (`src/`)

- **`gen/api/`** — API layer generated by Kubb from `openapi.json` (git-ignored). Never edit by hand.
- **`components/`** — app components: `status` (404, route error, splash, error feedback), `brand`, `devtools-wrapper`.
- **`core/`** — app-level constants and config: cache times, `info` (brand), `routes`, `phrases`, `alerts`, `themes`.
- **`hooks/`** — `use-custom-hook-options`: the hook Kubb's generated hooks call to get the cache updates / side effects defined in `custom-hook-options/`.
- **`lib/`** — configuration of external libs: `axios`, `env`, `tanstack-query`, `sentry-sdk`, `react-scan`, `infinite-list`.
- **`modules/`** — domain modules (`auth`, `form`, `header`, `landing-pages` here). Each has its own components, hooks and utils.
- **`routes/`** — file-based routes of TanStack Router (`_landing-pages` public layout, `auth`, `app` private area, `error`).
- **`schemas/`** — Zod schemas for forms and validation beyond what Kubb generates.
- **`styles/`** — Tailwind entry (`global.css`), base, utilities and animations.
- **`types/`** — global types, plus the generated route tree and image types.
- **`utils/`** — generic helpers.

## Useful scripts

Run from this folder:

- `bun run dev` — dev server (regenerates the route tree and image types first)
- `bun run build` / `bun run serve` — production build / preview
- `bun run build:prepare` — generate route tree, image types and the API layer; run it on a fresh clone and in CI
- `bun run ts:check` — TypeScript; `bun run lint` — Biome (run after every change); `bun run test` — Vitest
- `bun run tool:kubb` — regenerate the API layer; `bun run script:generate-openapi` — pull a fresh `openapi.json` from the backend
- `bun run script:optimize-images` — convert images to WebP and regenerate image types
- `bun run docker:build` — build the production image (from the repo root as context)

## Libs

Base UI components, forms, theme, toasts, alerts, infinite list and shared hooks/utils come from `packages/web/*` (`@web/*`); each has an `AGENTS.md`. App-specific code stays here; libs stay generic. The rules for the web live in `.agents/rules/web/`.

## Placeholders

Every page, text and asset is a placeholder (`FIXME`). The session (`modules/auth/utils/get-session.ts`) is fake and always logged in, the login form only shows a toast, and `openapi.json` has a single `/health` operation.
